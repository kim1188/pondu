# 흐름 F 작업 지시

당신은 kim1188/pondu 저장소에서 병렬 구현의 한 흐름을 맡았습니다. 대학생 실행 기록 앱(iPhone 앱 + Supabase 서버)을 아홉 개 흐름이 동시에 만들고 있고, 당신은 그중 흐름 F(ios-foundation)입니다. 이 세션을 지켜보는 사람은 없으니 질문하지 말고 합리적으로 결정한 뒤 보고에 적으세요.

먼저 읽을 것
- docs/specs/CONTRACT.md 전체. 흐름 사이의 약속이고, 함수 이름·인자·반환 모양·오류 코드·소유 경로가 여기 있습니다. 그대로 따르세요.
- docs/SRD.md, docs/PRD.md 중 당신 흐름에 해당하는 절. docs/specs/M0.md 4절과 5.2절, SRD 1·4·7절.

작업 규칙
- 브랜치 `ws/f-ios-foundation`에서 작업합니다(main에서 분기). 이 브랜치에만 커밋하고 푸시하세요. main에는 푸시하지 않고, 풀 리퀘스트도 만들지 않습니다.
- 계약 1절의 소유 경로만 고칩니다. 다른 흐름의 경로나 0001_schema.sql, docs/는 고치지 않습니다. 계약이 틀렸거나 부족하면 고치지 말고 보고에 "계약 변경 제안"으로 적으세요.
- 다른 흐름의 코드는 당신 브랜치에 없습니다. 그 흐름이 계약대로 만들 것이라 믿고 이름만 맞춰 쓰세요.
- 작업 단위마다 커밋하고, 끝나기 전에 반드시 푸시하세요. 컨테이너는 사라집니다.
- 커밋 메시지나 코드에 모델 이름을 적지 않습니다.

iOS 흐름 공통
- 이 컨테이너는 리눅스라 Xcode가 없고 SwiftUI를 빌드할 수 없습니다. `which swift`로 확인만 하고, 없으면 도구를 설치하려고 시간을 쓰지 마세요. 코드를 컴파일해 보지 못한다는 뜻이니 API 이름과 타입을 특히 신중하게 쓰고, 보고에 "빌드하지 못함"을 분명히 적으세요.
- 계약 5절의 구조와 이름을 그대로 따릅니다. PonduCore가 제공한다고 적힌 것(Backend, JSONValue, 모델, RemoteImage, skeleton, Theme 등)은 흐름 F가 만듭니다. 당신 타깃에서 다시 정의하지 말고 `import PonduCore`로 쓰세요. 계약에 없는데 필요한 공용 부품은 당신 타깃 안에 internal로 두고 보고에 적으세요.
- 화면과 로직을 나눕니다. 로직은 `@Observable` 모델 클래스에 두고 Backend 프로토콜만 의존하게 해서, 가짜 Backend로 XCTest를 쓸 수 있게 하세요. 테스트 파일도 작성하세요(실행은 못 합니다).
- 계약 5절의 성능 규칙을 지키세요: 뼈대 화면, 누르는 즉시 반영 후 실패 시 되돌리기, 20개씩 커서, 화면당 서버 함수 하나, async let, 시간 제한.
- 화면 문구는 한국어. 기록 방식 표시는 `앱 촬영 첨부`, `사진 없는 기록`, `나중에 정정함`, `오프라인 시작`처럼 방식만 말하고 "인증"이라는 말을 쓰지 않습니다(PRD 5·6절).
- 외부 라이브러리를 추가하지 않습니다.

할 일
- `ios/project.yml`(XcodeGen), `ios/App/`(앱 진입점, 진입 규칙, 탭 3개, 설정 화면, Info.plist의 카메라·캘린더·알림 권한 문구), `ios/PonduKit/Package.swift`(계약의 타깃 전부와 테스트 타깃 선언. 다른 흐름의 폴더가 비어 있으면 패키지가 깨지므로 각 기능 타깃 폴더에 빈 자리표시 파일을 두지 말고, README에 병합 후 빌드 순서를 적으세요).
- PonduCore 전체: 계약 5절에 적힌 프로토콜·타입·모델·화면 부품·도구를 이름 그대로. Backend의 실제 구현(SupabaseBackend: supabase-swift로 rpc·functions·storage 호출, 오류 코드를 BackendError로 변환, 시간 제한, 같은 요청 합치기), 인증 상태 저장소, 내 프로필 기기 캐시(SwiftData), 이미지 디스크 캐시, 백그라운드 업로드, MetricKit 수집.
- 다른 흐름이 테스트에 쓸 `FakeBackend`를 PonduCore에 공개로 넣으세요(함수 이름별 응답을 등록하고 호출 기록을 남기는 형태).
- FeatureAuth: M0 명세 4.1절의 화면(메일 입력, 코드 입력, 프로필 만들기)과 ProfileEditView.
- 앱 껍데기는 계약의 공개 뷰(SessionController, SessionHostView, RecordRootView, TogetherRootView, TodayRootView)를 이름 그대로 연결하세요.
- supabase-swift의 API는 기억이 틀릴 수 있습니다. 가능하면 공식 저장소나 문서를 확인하고, 확인하지 못한 호출은 보고에 목록으로 적으세요.
- `ios/README.md`에 Mac에서 처음 여는 방법(XcodeGen 설치, 프로젝트 생성, 프로젝트 주소와 공개용 키를 넣는 위치)을 적으세요.
