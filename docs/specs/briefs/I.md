# 흐름 I 작업 지시

당신은 kim1188/pondu 저장소에서 병렬 구현의 한 흐름을 맡았습니다. 대학생 실행 기록 앱(iPhone 앱 + Supabase 서버)을 아홉 개 흐름이 동시에 만들고 있고, 당신은 그중 흐름 I(ios-today)입니다. 이 세션을 지켜보는 사람은 없으니 질문하지 말고 합리적으로 결정한 뒤 보고에 적으세요.

먼저 읽을 것
- docs/specs/CONTRACT.md 전체. 흐름 사이의 약속이고, 함수 이름·인자·반환 모양·오류 코드·소유 경로가 여기 있습니다. 그대로 따르세요.
- docs/SRD.md, docs/PRD.md 중 당신 흐름에 해당하는 절. PRD 7절(오늘), 8절 흐름 A·B·D, 9.3·9.4·9.5절. SRD 3.1·3.2절과 4절.

작업 규칙
- 브랜치 `ws/i-ios-today`에서 작업합니다(main에서 분기). 이 브랜치에만 커밋하고 푸시하세요. main에는 푸시하지 않고, 풀 리퀘스트도 만들지 않습니다.
- 계약 1절의 소유 경로만 고칩니다. 다른 흐름의 경로나 0001_schema.sql, docs/는 고치지 않습니다. 계약이 틀렸거나 부족하면 고치지 말고 보고에 "계약 변경 제안"으로 적으세요.
- 다른 흐름의 코드는 당신 브랜치에 없습니다. 그 흐름이 계약대로 만들 것이라 믿고 이름만 맞춰 쓰세요.
- 작업 단위마다 커밋하고, 끝나기 전에 반드시 푸시하세요. 컨테이너는 사라집니다.
- 커밋 메시지나 코드에 모델 이름을 적지 않습니다.

iOS 흐름 공통
- 이 컨테이너는 리눅스라 Xcode가 없고 SwiftUI를 빌드할 수 없습니다. `which swift`로 확인만 하고, 없으면 도구를 설치하려고 시간을 쓰지 마세요. 코드를 컴파일해 보지 못한다는 뜻이니 API 이름과 타입을 특히 신중하게 쓰고, 보고에 "빌드하지 못함"을 분명히 적으세요.
- 계약 5절의 구조와 이름을 그대로 따릅니다. PonduCore가 제공한다고 적힌 것(Backend, JSONValue, 모델, RemoteImage, skeleton, Theme 등)은 흐름 F가 만듭니다. 당신 타깃에서 다시 정의하지 말고 `import PonduCore`로 쓰세요. 계약에 없는데 필요한 공용 부품은 당신 타깃 안에 internal로 두고 보고에 적으세요.
- 화면과 로직을 나눕니다. 로직은 `@Observable` 모델 클래스에 두고 Backend 프로토콜만 의존하게 해서, 가짜 Backend로 XCTest를 쓸 수 있게 하세요. 테스트 파일도 작성하세요(실행은 못 합니다).
- 계약 5절의 성능 규칙을 지키세요: 뼈대 화면, 누르는 즉시 반영 후 실패 시 되돌리기, 20개씩 커서, 화면당 서버 함수 하나, async let, 시간 제한.
- 화면 문구는 한국어. 기록 방식 표시는 `앱 촬영 첨부`, `사진 없는 기록`, `나중에 정정함`, `오프라인 시작`처럼 방식만 말하고 "인증"이라는 말을 쓰지 않습니다(PRD 5·6절).
- 외부 라이브러리를 추가하지 않습니다.

할 일
- FeatureToday: 오늘 화면(고정 일정, 지금 시작할 수 있는 일과 `지금 시작`, 진행 중 세션, 남은 할 일, 비서 진입점, 한 줄 입력창). `get_today` 하나로 그리고 기기 저장분으로 먼저 표시합니다. `지금 시작`은 deps.sessions.presentStart를 부릅니다.
- 할 일과 이어가는 일의 추가·수정·완료·삭제, 예정 시간 만들기·옮기기·고정하기.
- 캘린더 읽기(EventKit, iOS 17의 전체 접근 요청). 읽을 캘린더를 사용자가 고르고, 원본에 쓰는 API는 호출하지 않습니다. 일정 제목은 기기 밖으로 보내지 않고, 비서 요청에는 바쁜 시간 구간(start, end)만 넣습니다. 앱 실행·복귀·계획 직전에 갱신합니다.
- 예정 시각 로컬 알림(UserNotifications). 알림을 누르면 시작 화면으로 갑니다. 예정 시간이 바뀌면 알림을 다시 잡습니다.
- 비서: 한 줄 입력(capture), 하루 정리(plan_day), 남은 일 조정(reschedule, 세션이 `더 해야 해요`로 끝난 뒤에도 제안). `stream(function: "assistant")`의 message_delta를 받는 대로 표시하고 proposal이 오면 초안 카드로 보여 줍니다. 항목별로 고르거나 전부 적용(`apply_proposal`). 적용 전에는 아무것도 저장되지 않습니다. 보정된 예상 시간이면 배수를 알려 줍니다. 실패하면 직접 입력으로 넘어갑니다. 첫 사용 전 동의 화면(무엇이 서버와 AI로 가는지: 입력 문장, 할 일 제목, 바쁜 시간 구간).
- 가져오기: 텍스트 붙여넣기와 스크린샷 한 장(PhotosPicker는 보관함 권한 없이 동작합니다) → import-extract → 후보 미리보기(애매한 항목 표시) → 고른 것만 import_todos.
- 테스트: 바쁜 시간 계산, 알림 예약 계산, 스트림 이벤트 처리, 제안 일부 적용, 가져오기 중복 표시.
