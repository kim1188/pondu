# 흐름 G 작업 지시

당신은 kim1188/pondu 저장소에서 병렬 구현의 한 흐름을 맡았습니다. 대학생 실행 기록 앱(iPhone 앱 + Supabase 서버)을 아홉 개 흐름이 동시에 만들고 있고, 당신은 그중 흐름 G(ios-session)입니다. 이 세션을 지켜보는 사람은 없으니 질문하지 말고 합리적으로 결정한 뒤 보고에 적으세요.

먼저 읽을 것
- docs/specs/CONTRACT.md 전체. 흐름 사이의 약속이고, 함수 이름·인자·반환 모양·오류 코드·소유 경로가 여기 있습니다. 그대로 따르세요.
- docs/SRD.md, docs/PRD.md 중 당신 흐름에 해당하는 절. PRD 5·6절과 8절 흐름 B, 9.2·9.6절. SRD 3.3절과 4절.

작업 규칙
- 브랜치 `ws/g-ios-session`에서 작업합니다(main에서 분기). 이 브랜치에만 커밋하고 푸시하세요. main에는 푸시하지 않고, 풀 리퀘스트도 만들지 않습니다.
- 계약 1절의 소유 경로만 고칩니다. 다른 흐름의 경로나 0001_schema.sql, docs/는 고치지 않습니다. 계약이 틀렸거나 부족하면 고치지 말고 보고에 "계약 변경 제안"으로 적으세요.
- 다른 흐름의 코드는 당신 브랜치에 없습니다. 그 흐름이 계약대로 만들 것이라 믿고 이름만 맞춰 쓰세요.
- 작업 단위마다 커밋하고, 끝나기 전에 반드시 푸시하세요. 컨테이너는 사라집니다.
- 커밋 메시지나 코드에 모델 이름을 적지 않습니다.

iOS 흐름 공통
- 이 컨테이너는 리눅스라 Xcode가 없고 SwiftUI를 빌드할 수 없습니다. `which swift`로 확인만 하고, 없으면 도구를 설치하려고 시간을 쓰지 마세요. 코드를 컴파일해 보지 못한다는 뜻이니 API 이름과 타입을 특히 신중하게 쓰고, 보고에 "빌드하지 못함"을 분명히 적으세요.
- 계약 5절의 구조와 이름을 그대로 따릅니다. PonduCore가 제공한다고 적힌 것(Backend, JSONValue, 모델, RemoteImage, skeleton, Theme 등)은 흐름 F가 만듭니다. 당신 타깃에서 다시 정의하지 말고 `import PonduCore`로 쓰세요. 계약에 없는데 필요한 공용 부품은 당신 타깃 안에 internal로 두고 보고에 적으세요.
- 화면과 로직을 나눕니다. 로직은 `@Observable` 모델 클래스에 두고 Backend 프로토콜만 의존하게 해서, 가짜 Backend로 XCTest를 쓸 수 있게 하세요. 테스트 파일도 작성하세요(실행은 못 합니다).
- 계약 5절의 성능 규칙을 지키세요: 뼈대 화면, 누르는 즉시 반영 후 실패 시 되돌리기, 20개씩 커서, 화면당 서버 함수 하나, async let, 시간 제한.
- 화면 문구는 한국어. 기록 방식 표시는 `앱 촬영 첨부`, `사진 없는 기록`, `나중에 정정함`, `오프라인 시작`처럼 방식만 말하고 "인증"이라는 말을 쓰지 않습니다(PRD 5·6절).
- 외부 라이브러리를 추가하지 않습니다.

할 일
- FeatureSession: `SessionController`(계약의 SessionControlling 구현), `SessionHostView`. 시작 화면(분야, 이어가는 일, 공개 대상, 사진 찍기 또는 건너뛰기), 진행 중 막대(경과 시간은 그 글자만 갱신), 일시 정지·재개, 종료 화면(끝냈어요 / 더 해야 해요 / 오늘은 여기까지 + 선택 메모), 종료 확인 필요 처리(confirm_end).
- 인앱 카메라(AVFoundation). 사진 보관함에서 고르는 경로를 만들지 않습니다. 촬영 직후 1600px·480px HEIC 두 장으로 줄여 백그라운드로 올리고, 세션 시작은 업로드를 기다리지 않습니다.
- 시작은 누르는 즉시 화면에 반영하고 `p_client_id`로 재시도해도 한 번만 만들어지게 하세요. 오프라인이면 기기에 기록했다가 연결되면 `p_offline_started_at`으로 보냅니다.
- 경과 시간은 서버가 준 started_at과 paused_seconds로 계산합니다. 기기 시계를 바꿔도 기록이 바뀌지 않아야 합니다.
- FeatureRecord: 잔디(기록이 남은 날), 분야별 시간, 이어가는 일별 이력, 세션 목록(커서). 기기에 저장한 값으로 먼저 그리고 갱신합니다.
- 테스트: 경과 시간 계산, 상태 전이에 따른 화면 상태, 실패 시 되돌리기, 오프라인 대기열, 사진 크기 계산.
