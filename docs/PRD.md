## 1. 한 문장 정의

> 해야 할 일을 내 하루에 맞게 정리해 주고, 실제로 시작한 활동이 기록으로 남아 친구들과 자연스럽게 이어지는 대학생활 앱.

세 가지가 한 흐름으로 이어진다.

1. **비서**가 할 일을 정리하고 시간을 잡아 준다.
2. **세션**이 실제로 시작하고 끝낸 활동을 기록한다.
3. **공유**는 계획이 아니라 실행한 것 중 사용자가 고른 내용만 나간다.

## 2. 풀려는 문제

| 문제 | 지금의 대안 | 부족한 점 |
|---|---|---|
| 열심히 사는 모습을 보여 주고 싶다 | 셋로그, 인스타 스토리 | 시간이 되면 찍는 일상 기록이거나, 꾸민 결과물 위주 |
| 하지도 않은 일을 올리기 쉽다 | 투두 앱의 체크 표시 | 전부 자기 신고이고 사후 입력이 자유롭다 |
| 계획과 실행이 따로 논다 | 캘린더 + 투두 앱 + 타이머 | 계획이 틀어졌을 때 다시 잡아 주는 것이 없다 |
| 앱을 옮기려면 다시 입력해야 한다 | 수동 입력 | 시작 부담이 커서 첫날 이탈한다 |

차별화 가설: **실행 중 생긴 변화(못 끝냄, 늦게 시작함)를 다음 계획에 반영해 주는 경험.**
"할 일 + 타이머 + AI + 친구" 조합 자체는 기존 앱에도 있으므로 조합이 아니라 이 연결을 차별점으로 삼는다.

## 5. 핵심 개념

사용자에게는 "하던 일 선택 → 시작 → 어디까지 했는지 남기기"로만 보이고, 내부에서 아래를 구분한다.

| 개념 | 의미 | 예시 |
|---|---|---|
| 이어가는 일 | 여러 날에 걸친 활동의 맥락 | 개인 앱 개발, DB 과제, 이번 학기 알바 |
| 할 일 | 달성하려는 구체적인 결과 | 로그인 오류 수정, 과제 1번 제출 |
| 예정 시간 | 그 일을 하려고 잡아 둔 시간 | 오늘 15:00~16:00 |
| 세션 | 사용자가 시작·종료한 실제 활동 구간 | 15:12 시작, 15:57 종료 |
| 진척 | 어디까지 했는지에 대한 사용자 설명 | "원인은 찾았고 수정은 남음" |
| 공유 카드 | 친구에게 보이는 표현 | "로그인 문제 해결 중" |

### 반드시 지키는 규칙

1. **세션 종료와 할 일 완료는 별개다.** 한 시간을 했어도 못 끝낼 수 있고, 한 세션에 여러 개를 끝낼 수도 있다.
2. **세션은 실시간으로만 만든다.** 과거 시각으로 시작하거나 사후에 세션을 추가할 수 없다.
3. **비서는 세션을 만들거나 세션 시간을 바꿀 수 없다.** 계획 제안과 할 일 정리만 한다.
4. **할 일 완료는 사용자의 명시적 표시로만 처리한다.** "제출했어"라고 말하면 비서가 완료로 바꿀 수 있고, 근거는 "사용자 진술"로 남긴다.
5. **가져온 데이터는 실행 기록이 되지 않는다.** 캘린더 일정이나 다른 앱의 완료 표시는 출처와 함께 보여 줄 뿐 세션으로 바꾸지 않는다.
6. **계획은 기본 비공개, 공유는 사용자가 고른다.** 계획을 공유할 때는 "예정"으로 표시해 실행 기록과 구분한다.
7. **기록 방식을 있는 그대로 표시한다.** "인증됨" 같은 등급 대신 `앱 촬영 첨부`, `사진 없는 기록`, `나중에 정정함`처럼 방식을 적는다.

## 6. 조작 방지의 목표와 한계

완벽한 차단은 목표가 아니다. 사진을 찍고 타이머를 방치하는 것은 막을 수 없다. 목표는 세 가지다.

1. 과거 기록을 방금 한 것처럼 보이게 하는 경로를 없앤다(갤러리 업로드 금지, 서버 시각 기록, 소급 금지).
2. 앱이 관측한 것과 사용자가 말한 것을 구분해 표시한다.
3. 시간을 부풀려서 얻는 이익을 줄인다(랭킹 없음, 종료를 잊은 세션은 누적에 자동 반영하지 않음).

| 상황 | 허용 | 표시 |
|---|---|---|
| 사진을 남길 수 있음 | 실시간 시작 + 인앱 촬영 | `앱 촬영 첨부` |
| 사진이 곤란함(연구실, 인턴, 알바) | 실시간 시작 + 선택 메모 | `사진 없는 기록` |
| 끝난 뒤에 정리함 | 개인 메모, 할 일 완료 입력 | `나중에 남긴 기록` (세션 아님) |

화면 문구도 관측한 범위만 말한다. `세션 시작 후 37분`은 쓰고, `37분 집중 인증`은 쓰지 않는다.

## 7. 화면 구성 (탭 3개)

### 오늘
- 오늘의 고정 일정(가져온 캘린더)
- 지금 시작할 수 있는 일과 `지금 시작` 버튼
- 진행 중인 세션
- 남은 할 일
- 비서 진입점: `하루 정리`, `남은 일 조정`, 한 줄 입력창

### 함께
- 친구의 최신 세션(진행 중인 것이 위)
- 크루의 기록
- 카드에서 `지난 기록` 열기, 반응, 한마디
- 진행 중인 카드의 `같이 하기`: 누르면 내 세션이 시작되고 "가온과 함께"로 표시된다
- 시간순 정렬. 시간이 많은 사람을 위로 올리지 않는다.

### 기록
- 날짜별 기록과 잔디(기록이 남은 날)
- 분야별 세션 시간
- 이어가는 일별 이력
- 완료한 할 일
- 주간 돌아보기(비서)

친구가 없어도 `오늘`과 `기록`만으로 쓸 이유가 있어야 한다. 이것이 초기 빈 피드 문제에 대한 대응이다.

## 8. 핵심 사용 흐름

### 흐름 A — 하루 정리
1. 사용자가 입력: "오늘 DB 과제 조금 하고, 앱 로그인 문제도 고쳐야 해. 저녁에는 운동."
2. 비서가 캘린더의 바쁜 시간을 피해 초안을 보여 준다.
3. 사용자가 전체 적용하거나 일부만 고친다.
4. 예정 시각에 로컬 알림이 예약된다.

비서는 사용자가 말하지 않은 마감이나 목표를 만들어 내지 않는다. 애매한 부분은 미정으로 두거나 그 부분만 묻는다.

### 흐름 B — 세션 시작과 종료
1. 알림 또는 `오늘` 화면에서 `지금 시작`을 누른다. 제목, 분야, 연결된 할 일은 이미 채워져 있다.
2. 사진을 남기면 인앱 카메라가 열린다. 건너뛸 수 있다.
3. 공개 대상(나만, 친구, 크루)은 이어가는 일의 기본값을 따르고 그 자리에서 바꿀 수 있다.
4. 종료할 때 하나를 고른다: `끝냈어요` / `더 해야 해요` / `오늘은 여기까지`. 메모는 선택.
5. `더 해야 해요`면 비서가 이어 할 시간을 제안한다.

알림을 받았거나 예정 시각이 됐다고 세션이 자동으로 시작되지는 않는다.

### 흐름 C — 친구가 보는 화면
> **가온 · DB 과제**
> 15:12에 시작 · `앱 촬영 첨부`
> "1번 문제 접근법 보는 중"
> `같이 하기` `지난 기록` `수고했어` `한마디`

`같이 하기`는 구경이 세션 시작으로 이어지게 하는 장치다. 상대와 같은 분야로 내 세션이 바로 시작되고, 두 카드에 서로의 이름이 붙는다. 함께 했다는 표시일 뿐 상대의 기록을 바꾸지 않는다.

### 흐름 D — 가져오기
1. 온보딩에서 iPhone 캘린더 권한을 요청하고, 읽을 캘린더를 사용자가 고른다.
2. 투두 앱·시간표는 텍스트를 붙여 넣거나 스크린샷을 올린다.
3. 앱이 후보 항목을 뽑아 보여 주고, 애매한 항목을 표시한다.
4. 사용자가 확인한 항목만 저장한다.

## 9. MVP 기능 요구사항

우선순위: P0은 출시 필수, P1은 MVP에 넣되 일정이 밀리면 뺄 수 있는 것.

### 9.1 가입과 관계
| ID | 요구사항 | 우선순위 |
|---|---|---|
| A-1 | @korea.ac.kr 메일로 인증 코드를 받아 가입·로그인한다 | P0 |
| A-2 | 프로필: 이름, 아이디, 사진, 학과(직접 선택) | P0 |
| A-3 | 아이디 검색 또는 초대 링크로 친구 요청, 수락, 삭제 | P0 |
| A-4 | 크루: 누구나 만들 수 있고 초대 링크로 입장한다. 운영자는 내보낼 수 있다 | P1 |
| A-5 | 사용자 차단, 게시물 신고 | P0 |
| A-6 | 계정 삭제(데이터 포함) | P0 |

표시 문구는 "고려대 메일 확인"으로 한다. 졸업생도 같은 주소를 쓸 수 있어 재학 증명이 아니다.
학과는 프로필에 표시만 하고 공개 범위로는 쓰지 않는다. 서로 모르는 사람이 많은 학과보다 실제로 함께 움직이는 크루가 반응이 생기기 쉽고, 출시도 실제 그룹 2~3개에서 시작할 수 있다.
A-5와 A-6은 App Store 심사 요건이다.

- 안드로이드, 웹

## 11. 성공 지표 (초기 목표치, 출시 후 조정)

| 지표 | 무엇을 보는가 |
|---|---|
| 첫날 계획 생성률 | 가져오기와 비서가 시작 부담을 줄이는가 |
| 계획 → 세션 전환율 | 잡아 둔 시간에 실제로 시작하는가 |
| 재배치 수락률 | 비서의 다시 잡기 제안이 쓸 만한가 |
| 같이 하기로 시작된 세션 비율 | 피드가 실행으로 이어지는가 |
| 예상 대비 실제 시간 오차 | 보정이 계획을 더 맞게 만드는가 |
| 주 3일 이상 기록한 사용자 비율 | 습관이 되는가 |
| 친구 1명 이상 연결 비율 | 공유 가치가 생기는가 |
| 4주 차 유지율 | 계속 쓰는가 |

숫자 목표는 첫 테스트 그룹(지인 20~30명)의 결과를 본 뒤 정한다.

## 12. 위험과 대응

| 위험 | 조기 신호 | 대응 |
|---|---|---|
| MVP 범위가 1인 개발에 크다 | 마일스톤 하나가 2주 넘게 걸림 | SRD의 마일스톤 순서대로, P1부터 뺀다 |
| 비서가 기한을 지어내거나 일정을 겹치게 잡는다 | 시험 세트의 통과율 하락 | 규칙 검사 코드가 저장을 막고, 프롬프트를 고칠 때마다 시험 세트를 다시 돌린다 |
| 비교 피로 | 피드 열람은 많은데 세션 시작이 줄어듦 | 랭킹 없음 유지, 시간보다 사람과 진척을 앞에 둔다 |
| 빈 피드 | 친구 0명 사용자의 이탈 | 개인 가치(오늘, 기록) 우선, 지인 그룹 단위 초대 |
| 비서 비용 | 사용자당 호출 수 급증 | 일일 한도, 가벼운 모델 우선, 규칙 처리로 대체 가능한 것은 코드로 |
| 일정 데이터 노출 우려 | 캘린더 권한 거부율 | 바쁜 시간 구간만 서버로 보냄, 동의 화면에 명시 |
| 학교 메일 수신 지연·차단 | 인증 코드 미도착 문의 | 전용 발송 서비스 사용, 재전송, 테스트로 사전 확인 |
| 사진 속 타인·민감 정보 | 신고 발생 | 신고·차단, 사진 없는 기록 허용 |

## 13. 구현 전에 확인할 것

- 에브리타임의 외부 캘린더 연동이 시간표를 iPhone 캘린더로 내보내는지. 된다면 I-1로 해결되고 스크린샷 변환은 보조가 된다.
- 투두메이트에 내보내기 기능이 있는지. 공개 자료에서는 확인하지 못했다.
- 고려대 메일이 외부 발송 인증 코드를 스팸으로 분류하는지.
